# M27 — Audio & Ambient Layer

**Status:** 🔲 planned
**Depends on:** M12 (UX & Presentation Polish 2.0)

---

## Goal

Enhance the game's atmosphere by implementing a formal ambient sound/visual layer. This includes expanding the terminal bell (beep) system into a multi-context sound effect queue and surfacing region-specific "ambient tags" in the UI to provide environmental context.

---

## Scope

- **Sound Effect Engine**:
    - Replace `App::pending_beep: Cell<bool>` with a `SoundQueue` or similar.
    - Define a `SoundEffect` enum: `Beep`, `LowBeep`, `HighBeep`, `DoubleBeep`.
    - Map `SoundEffect` to game events:
        - `TakeDamage` -> `LowBeep`
        - `LootItem` -> `HighBeep`
        - `LevelUp` -> `DoubleBeep`
        - `QuestComplete` -> `HighBeep` then `LowBeep`.
- **Ambient UI Component**:
    - Surface the `ambient` tag defined in `region.toml` in the TUI HUD.
    - Add environmental "flavor text" triggers that fire periodically based on the ambient tag.
- **Audio Toggle Persistence**:
    - Ensure the 'b' toggle state is saved/loaded or at least respected across major state transitions correctly.

---

## Target Files

- `src/app.rs`: State for sound queue and ambient triggers.
- `src/renderer.rs`: Define `SoundEffect` in a renderer-agnostic way.
- `src/ui/tui/mod.rs`: Implementation of beep patterns using terminal escape codes.
- `src/ui/tui/screens/world_map.rs`: HUD updates for ambient tags.

---

## Done When

- [ ] `SoundEffect` enum exists and is used by `App` to queue sounds.
- [ ] At least 3 different game events trigger distinct beep patterns.
- [ ] The current region's `ambient` tag (e.g., "Ash Drift") is visible on the World Map screen.
- [ ] Atmospheric flavor text (e.g., "Ash drifts through the air...") appears in the log periodically for regions with ambient tags.
- [ ] `cargo test` passes.
